Like any field of research that relies on computational methods, computational humanities depends on high-quality or “good” code to produce reliable, reproducible research results. Code quality assessment is context-dependent; functionality matters more than style for code accompanying a paper, and reusable software tools have a higher bar for quality, but there is still not full agreement on code quality or code review; even at CHR, not all papers are accompanied by code, and when present it can not always be run (Illmer 2025).  The approach proposed by [CODECHECK project](https://codecheck.org.uk/) (Eglen and Nüst 2019) is a workflow where another person tries to run the code for a paper and reproduce the research results and figures. This is a practical, low bar approach to improve reproducibility; their process provides recognition for code authors and code checkers, and improves quality because authors are aware that someone else will be running their code. 

We are organizing a CODECHECK workshop for CHR2027 as a way of bringing the idea of code checks to CHR, so we can work together to test its relevance and usefulness for this community. Workshop participants will learn about code review and reproducibility efforts at computational humanities journals, receive basic training and guidelines for code checking, and gain practical experience in completing a code check. A CODECHECK project team member or affiliate will join (remotely or in person, TBD) to help provide context and training. Workshop presenters will provide context from other related efforts, including the Journal of Computational Literary Studies (JCLS) data and code review process; Computational Humanities Research journal requirements and review; and DHTech Community Code Review. 

We expect participants to complete a handful of code checks during the workshop, and we will summarize the workshop in a written report after the fact to share the results of the code checks, workshop participants’ reflections on the experience, and potential value for the CHR community.

Participants will be expected to bring a laptop with admin rights so they can install any necessary software; a mix of domain and technical expertise is also beneficial. 

We particularly welcome graduate students and early career researchers; as the CODE CHECKS guidelines note, “codechecks are an excellent opportunity to involve early career researchers (ECRs) or research software engineers (RSEs) in peer review.” 

## Workshop schedule 

*(preliminary, subject to change)*

- 30min: Introductions of Codecheck, DHTech Code Review, JCLS, and CHR approaches 
- 30min: Lightning talks of projects to be code checked (~6 papers)
- 5 minutes: Brief background; Language/technologies; What to be checked
    - Break 10 min
- 50min: Code Checking in groups
    - Break up into teams of 4 
- 30min: Groups report back findings to plenum including collective note taking for write up
- 30min: Wrap up discussion
